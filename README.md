# StatEdge site

Static site (HTML, CSS and JavaScript, no build step). Serve the folder with any static server, for example `npx serve .`, and open the address it prints.

- `data/profile.json`: name, about text, skills and contact links.
- `data/case-studies.json`, `data/findings.json`: written copy.
- `data/showcase.json`: generated numbers. Do not edit by hand.
- `node scripts/check.mjs`: run before publishing. It checks the data files and scans public files for wording that should not appear on the site.

Keep public copy about results and what they mean. Do not describe how the numbers are produced, and keep the uncertainty wording on every projection.

- `data/case-studies.json` is generated by the internal tool (the original conclusions are kept word for word, with deeper analysis added; every number in the added text is read from the match data). Do not edit by hand.

## Refreshing the site from the internal tool

Run one command from this folder (`C:\Projects\statedge-site`):

```
npm run refresh
```

It runs the internal tool (`C:\Projects\IPL`) in order: rebuild the team table, export the showcase and players, rebuild the case-study evidence and copy, then run the leak check. It stops at the first failure and takes about 10 minutes. Preview afterwards with `npm start` (http://localhost:4173).

### After changing a player's batting or bowling style

```
npm run refresh:styles
```

Rebuilds everything that depends on styles: roles and class, style tables, player abilities, the next-ball model, every team's strength, the left-right research and the site data, then runs the checks and a browser smoke test. It skips every stage that is already up to date, and does nothing if no style changed. `npm run refresh` also catches up on a style change. Details: `C:\Projects\IPL\project_requirements\STYLE_CHANGE_REFRESH.md`.

Run these first, only when match data or player history changed (from `C:\Projects\IPL`):

```
uv run python -m ipl.analytics.build_player_class
uv run python -m ipl.analytics.build_player_index
```

Kept by hand in the internal tool: `src/ipl/analytics/data/captains.json` (captains and vice-captains; update it when they change, then run `npm run refresh`) and the squads in Squad Management.
Do not edit `data/showcase.json`, `data/players.json` or `data/case-studies.json` by hand.
